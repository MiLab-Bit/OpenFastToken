### 方式 3: 使用 Python 脚本

#### 步骤 1: 创建迁移脚本

```python
# migrate_oauth.py
import sqlite3
import os

db_path = r"Z:\Dev\FastToken\one-api.db"
backup_path = r"Z:\Dev\FastToken\one-api-backup-20260530.db"

# 检查备份是否存在
if not os.path.exists(backup_path):
    print("错误: 备份文件不存在，请先备份数据库！")
    exit(1)

print(f"连接数据库: {db_path}")
conn = sqlite3.connect(db_path)
cursor = conn.cursor()

try:
    # 删除自定义 OAuth 表
    print("删除 custom_oauth_providers 表...")
    cursor.execute("DROP TABLE IF EXISTS custom_oauth_providers")
    
    print("删除 user_oauth_bindings 表...")
    cursor.execute("DROP TABLE IF EXISTS user_oauth_bindings")
    
    # 提交更改
    conn.commit()
    print("✅ 迁移成功！")
    
    # 验证
    cursor.execute("SELECT name FROM sqlite_master WHERE type='table' AND name IN ('custom_oauth_providers', 'user_oauth_bindings')")
    result = cursor.fetchall()
    
    if len(result) == 0:
        print("✅ 验证成功：表已被删除")
    else:
        print(f"⚠️ 警告：仍有残留表: {result}")
        
except Exception as e:
    print(f"❌ 迁移失败: {e}")
    conn.rollback()
finally:
    conn.close()
```

#### 步骤 2: 执行脚本

```powershell
python migrate_oauth.py
```

### 方式 4: 重启 FastToken 服务 (最简单)

由于我们已经在代码中删除了自定义 OAuth 功能，FastToken 启动时会自动：
1. 忽略不存在的表
2. 不访问废弃的字段

所以，**你甚至不需要立即删除这些表！** 它们只是占用一点磁盘空间，不会影响程序运行。

只需重启服务：

```powershell
# 停止服务
# (根据你的部署方式选择)

# 重启服务
cd Z:\Dev\FastToken
go run main.go
```

## ⚠️ 重要说明

### 关于 users 表的废弃字段

SQLite 不支持 `DROP COLUMN`，但我们**不需要**删除这些字段：

| 字段名 | 状态 | 影响 |
|--------|------|------|
| `discord_id` | 已在代码中删除 | ❌ 不影响运行 |
| `oidc_id` | 已在代码中删除 | ❌ 不影响运行 |
| `telegram_id` | 已在代码中删除 | ❌ 不影响运行 |
| `linux_do_id` | 已在代码中删除 | ❌ 不影响运行 |

**原因:**
- Go 代码已经删除了这些字段的引用
- GORM ORM 会自动忽略代码中不存在的字段
- 废弃字段只是保留在数据库中，永远不会被访问

**如果想彻底清理:**
需要重建整个 users 表（见 `20260530_remove_oauth_platforms_sqlite.sql` 文件），但这通常不是必须的。
